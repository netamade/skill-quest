# スキルガイド・デイリー目標の実装と確認

## 実装

- `engine.js`: ホームと再開導線を追加。既存の分野判定を `questionStats` に抽出し、分野・学習目標で同じ判定を使用する。学習目標は `objective` および `alsoCovers` の問題を対象とする。window / decay / minEvidence / excludeModes / coverageForTop / thresholds は変更していない。
- 弱点は config のラベル順で安定未満を抽出し、ラベル、直近加重正答率、回答回数の昇順に整列。各分野を直接練習できる。回答回数は反復を含み、総問題数と単位を区別して表示する。未回答の正答率は推定せず「—%」。
- デイリー目標は全製品共通で `kt:daily:v1` に `{v:1, goal, days:{"YYYY-MM-DD":{count, achieved}}}` を保存。既存の `kt:{product}:v1` の形式は維持。過去の履歴は移行・推定しない。
- 練習は採点時、模試は選択が揃った時点で1問として数える。模試の回答変更や終了時には重複計上せず、未回答はデイリーに含めない。既存の模試採点・記録は変更しない。
- 目標は3/5/10/20問、既定5問。端末のローカル日付を使用し、達成済みの日付からストリークを算出。当日未達でも昨日までの連続達成を表示する。目標変更で過去の達成は取り消さない。当日の目標を下げて達成した場合も1回だけ祝福する。
- `styles.css`: カード、モバイル優先の製品切替、44px以上の操作領域、キーボードフォーカス、コントラスト、動きの軽減設定。アクセントは製品の `theme.primary` を反映。
- `index.html` / `links.html`: 共通CSSを追加し、既存のGoogle Fontsへの参照を削除。外部依存を追加していない。`data.js` は変更なし。

## 確認結果

Chromium / Playwright によるブラウザ操作で次を確認した。

- 全5製品: ホーム、目標の既定値、configのテーマ色、分野練習、回答・採点、ホームからの再開、分野マップ、模試の回答と結果表示。
- 5製品の練習・模試の回答数合算、目標の保存・再読み込み。
- 時刻のない旧形式記録でエラーが出ないこと。学習目標内訳の件数が objectives の件数に一致すること。
- 目標到達時のトースト、再読み込みで重複しないこと、12月31日→1月1日の連続達成、翌日の進捗リセットとストリーク維持。
- 全分野マスターの場合の弱点なし表示と、学習目標内訳。弱点の並び順、安定分野の除外。
- 320px / 390px の横幅でホームの横はみ出しがなく、ボタン・目標選択が44px以上であること。1280pxの画面も確認。
- JSONエクスポート、ホーム・リンク集で外部リソースを要求しないこと。
- ブラウザのJavaScript例外なし。`node --check engine.js`、`git diff --check`、`git diff --exit-code HEAD -- data.js`。

## 手動での再確認

1. リポジトリで `python -m http.server 8000` を実行し `http://localhost:8000` を開く。
2. 各製品でホーム→分野の「練習する」→回答→ホーム→「練習を続ける」を操作し、次の問題から再開することを確認。分野マップと模試も操作する。
3. 目標を3問に設定し、練習・模試で合計3問回答する。祝福が1回表示され、ホームに達成・「もっと解く」が表示されることを確認。再読み込みとツール切替後も設定・回答数が維持されることを確認。
4. 開発者ツールのモバイル表示とキーボードで操作し、Networkで外部フォント等への要求がないことを確認。

GitHub Pagesは従来どおり静的配信のため、未訪問のページをネットワーク切断後に初めて開く保証（Service Worker等）は追加していない。
