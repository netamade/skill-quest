# 発注書：Power Automate の問題データを API から取得する（DB化試作のサイト側接続）

発行：2026-11-13（クロ）
対象リポジトリ：netamade/skill-quest
担当：Codex（作業ごとに新規タスクで実施すること）

## 背景

- SKILL QUEST の作問は日々ストックが増えるが、サイトへの反映は data.js の差し替え（PR）が必要で、即時反映できない。
- 試作として、Power Automate（tool id: `powerautomate`）の問題だけを Cloudflare D1 から読み取り専用 API で配信する仕組みを用意した。サイト側は、Power Automate を開いたときに API から問題を取得して表示する形に変更する。
- 他の5ツールは従来どおり data.js の静的データのままで、一切変更しない。

## API の仕様（デプロイ済み）

- ベースURL：`https://sq-questions-api.sola-labo.workers.dev`
- エンドポイント：`GET /v1/tools/powerautomate/questions`
- レスポンス（200）：

```json
{
"tool": "powerautomate",
"generatedAt": "2026-11-12T21:59:20.447Z",
"questions": [ /* 既存の問題スキーマ（data.js の bank の要素）と同形式のオブジェクト配列 */]
}
```

- `questions` の各要素は、既存の bank の問題オブジェクトと完全に同じ形式（id、type、domain、objective、choices（why 付き）、answer、explanation、source、status 等）。
- API はチェック済み（status: checked）の問題だけを返す。書き込み口はない。
- CORS は許可済み（GitHub Pages のオリジンから fetch 可能）。
- 現在、試作用のサンプル問題が1問（id: `PA-BAS-001`、タイトル相当の文面にと明記）入っている。検証はこの1問が返る前提で行うこと。

## 第1部：engine.js の変更

1. Power Automate のツール画面を開いたとき（タブ選択時）に、そのツールの bank が空なら、上記エンドポイントへ fetch する。
- 取得はページ読み込みごとに最大1回だけ（結果をメモリに保持し、再取得しない）。
- 成功したら、返ってきた `questions` をそのツールの bank として差し込み、問数表示・分野別の内訳・開始ボタンの有効化など、画面の状態を再描画する。
2. 取得に失敗した場合（通信エラー、200以外、JSON でない、`questions` が配列でない等）は、従来どおり「0問・準備中」の表示のままにする。エラーで画面が壊れないこと。
3. 取得した問題でのプレイ（出題・採点・復習・記録保存）が、静的データの問題とまったく同じに動くこと。
4. 学習記録（localStorage のキーと形式）には一切触らない。
5. 他の5ツールについては、fetch を行わず、表示・動作を一切変えない。
6. data.js は変更しない（Power Automate の config と空の bank は現行のまま）。

## 第2部：リリース情報欄の追加

トップ画面の既存メッセージ（バナー）の下に「リリース情報」欄を追加する。

1. data.js のトップレベルに `releaseNotes` 配列を追加する。各要素は `{ "date": "YYYY-MM-DD", "text": "一言"}`、新しい順に最大5件。
2. 初期データは次の1件のみ：
- `{ "date": "2026-11-13", "text": "Power Automate の問題配信をデータベース方式に切り替えました"}`
3. トップ画面ではバナーの下に、日付と一言を1行ずつ、最大5件まで表示する。空配列なら欄自体を表示しない。
4. 以後の運用：機能追加や問題投入の PR では、この欄に1行追記する（本体決定済みの運用ルール）。

## 禁止事項

- data.js の既存5ツールのデータ（config・bank）の変更。
- 第1部・第2部以外の機能追加、デザイン変更、リファクタリング。
- API の URL を定数以外（設定ファイル等）に分散させない。engine.js 内の1か所にまとめる。

## 完了条件

- PR を作成し、変更点と自己検証の結果を PR 本文に書くこと。
- 自己検証で最低限確認すること：
- Power Automate を開くと API から問題が読み込まれ、問数が変わり、プレイ・採点できる。
- API が止まっている想定（URL を一時的に無効なものへ変えたローカル確認等）でも、従来表示に落ちて画面が壊れない。
- 他の5ツールの表示・プレイが従来と変わらない。
- トップ画面にリリース情報が1件表示される。
- 検証（クロ）がマージ前に試作用サンプル問題を DB から取り除く。マージ後の本番では Power Automate は当面0問表示に戻り、チェック済み問題が DB に投入された分から即時反映されるのが正しい状態である。
